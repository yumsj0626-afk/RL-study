# 실험 C_ambiguous: 안전하게 (7,7)까지

## 입력
- 자연어 명령: "안전하게 (7,7)까지"
- 가설: LLM이 "안전하게"를 `preference=safe`로 해석하지만 `soft_avoid`가 비어 있으면 효과가 제한적이다.
- 성공 기준: 파싱 notes에 안전 선호 해석이 기록되고 학습이 완료된다.

## LLM 파싱 결과
```json
{
  "grid_size": [8, 8],
  "start": [0, 0],
  "goal": [7, 7],
  "obstacles": [],
  "soft_avoid": [],
  "preference": "safe",
  "interpretation_notes": "안전하게는 preference=safe로 해석하고, 목표는 (7,7)로 설정"
}
```

해석 노트: LLM은 "안전하게"를 의도대로 `preference=safe`에 매핑했다. 하지만 위험 구역이나 피해야 할 대상이 없어 안전 선호가 실제 reward에 작용할 대상은 없었다.

## 학습 결과
- 최종 평가 평균 reward: `87.0`
- greedy rollout 평균 경로 길이: `14.0`
- 성공률: `1.0`
- obstacle 진입 횟수: `0`
- timeout 횟수: `0`
- 예시 경로: `(0,0) -> (1,0) -> (1,1) -> (2,1) -> (2,2) -> (2,3) -> (2,4) -> (3,4) -> (4,4) -> (5,4) -> (6,4) -> (6,5) -> (6,6) -> (7,6) -> (7,7)`

## 가설 vs 실제 결과
가설은 부분적으로 충족됐다. 파서는 "안전하게"를 `safe`로 기록했고 학습도 성공했지만, `soft_avoid=[]`이므로 safe shaping은 사실상 비활성화됐다. 결과적으로 실험 A와 비슷하게 최단 길이 `14.0`의 일반 경로를 학습했다.

## 발견과 한계
자연어의 "안전"은 현재 v1 스키마에서 단독으로는 충분하지 않다. 안전 선호가 의미 있으려면 위험 구역, 사람/물체 위치, 금지 구역 같은 참조 대상이 함께 필요하다. 캡스톤에서는 "안전하게"가 기본 거리 확보, 속도 제한, collision margin 같은 구체적 제약으로 확장되어야 한다.
