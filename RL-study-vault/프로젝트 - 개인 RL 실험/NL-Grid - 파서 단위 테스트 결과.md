# 파서 테스트 결과 분석

| ID | 명령 | 상태 | LLM 해석 | 평가 |
|---|---|---|---|---|
| T01 | 오른쪽 아래 구석으로 가 | PASS | 오른쪽 아래 구석을 (7,7)로 해석 | 의도 일치 |
| T02 | (7,7)로 가는데 (4,4) 주변은 피해 | PASS | (4,4) 주변을 맨해튼 거리 1의 네 칸으로 해석하고, '피해'는 soft_avoid로 분류 | 제약을 hard/soft 영역으로 변환 |
| T03 | 안전하게 목표까지 | PASS | 안전하게는 preference=safe로 해석했지만 목표가 명시되지 않아 goal=null | 목표 미명시를 goal=null로 보존 |
| T04 | 빠르게 가 | PASS | 빠르게는 preference=shortest로 해석했지만 목표가 명시되지 않아 goal=null | 목표 미명시를 goal=null로 보존 |
| T05 | 왼쪽 위로 가되 가운데 칸은 절대 피해 | PASS | 왼쪽 위를 (0,0)으로 해석하고, 가운데 칸을 (3,3)으로 해석하여 절대 피해는 obstacles로 분류 | 의도 일치 |
| T06 | (0,7)로 가고 가장 짧게 가 | PASS | (0,7)을 목표로 설정하고, '가장 짧게'는 preference=shortest로 해석 | 의도 일치 |
| T07 | 오른쪽 아래 구석으로 가고 (3,3)~(3,5) 라인은 위험해 | PASS | 오른쪽 아래 구석을 (7,7)로 해석하고, (3,3)~(3,5) 라인을 포함한 세 칸을 soft_avoid로 분류 | 제약을 hard/soft 영역으로 변환 |
| T08 | 장애물 없이 목표까지 | PASS | 장애물이 없다는 것은 obstacles이 없음을 의미하지만, 목표가 명시되지 않아 goal=null | 목표 미명시를 goal=null로 보존 |
| T09 | (5,5)에서 출발해서 (0,0)까지 안전하게 | PASS | 출발지를 (5,5)로, 목표를 (0,0)으로 설정하고, '안전하게'는 preference=safe로 해석 | 의도 일치 |
| T10 | 가운데로 가 | PASS | 가운데를 (3,3)으로 해석했으며, 8x8 그리드에는 여러 중앙 셀이 있을 수 있음 | 모호성을 interpretation_notes에 기록 |

## 발견한 패턴
1. 명확한 좌표와 모서리 표현은 대부분 안정적으로 구조화된다.
2. 목표가 없는 명령은 `goal=null`로 남겨 builder 단계에서 통제된 실패로 처리한다.
3. "위험해", "주변" 같은 표현은 hard obstacle보다 soft avoidance로 해석하는 편이 의도 손실이 작다.
