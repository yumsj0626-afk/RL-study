# Part 1: Episodic Sarsa with Function Approximation

---

### Episodic Sarsa with Function Approximation

---

## 한 줄 요약

함수 근사 환경에서 제어(control)를 위해 **행동 가치 함수 Q(s, a)**를 근사해야 합니다. 특징 벡터를 행동마다 쌓는(stacking) 방식으로 이를 구현하고, Sarsa 업데이트를 함수 근사에 맞게 조정합니다.

---

## 핵심 개념 정리

### 왜 행동 가치 함수가 필요한가

V(s)만으로는 어떤 행동을 해야 더 좋은 상태로 갈 수 있는지 알 수 없습니다. 제어를 위해서는 Q(s, a)가 필요합니다.

---

### 행동 의존 특징 벡터: Feature Stacking

같은 상태 특징 $\mathbf{x}(s)$를 각 행동별로 별도로 복사하되, **현재 행동에 해당하는 세그먼트만 활성화**합니다.

예시: 특징 4개, 행동 3개:

```
행동 0 선택 시: [x1 x2 x3 x4 | 0  0  0  0  | 0  0  0  0 ]
행동 1 선택 시: [0  0  0  0  | x1 x2 x3 x4 | 0  0  0  0 ]
행동 2 선택 시: [0  0  0  0  | 0  0  0  0  | x1 x2 x3 x4]
```

총 특징 수 = 4 × 3 = 12. 가중치 벡터도 같은 구조로 나뉩니다.

$$\hat{q}(s, a, \mathbf{w}) = \mathbf{x}(s, a)^\top \mathbf{w}$$

행동별로 독립된 가중치 세그먼트를 사용하므로, 한 행동의 학습이 다른 행동에 영향을 미치지 않습니다.

---

### 신경망에서의 동일한 구조

신경망에서는 보통 **출력층에 행동 수만큼 출력 노드**를 두는 방식을 사용합니다.

- 입력: 상태 $s$
- 마지막 은닉층: 상태 특징 $\mathbf{x}$
- 출력: 각 행동의 가치 ($|\mathcal{A}|$개 노드)

이는 Feature Stacking과 수학적으로 동일합니다. 각 행동의 출력 가중치가 독립적이고 다른 행동의 가중치와 상호작용하지 않습니다.

> 행동을 일반화하려면 행동도 입력에 포함시켜 출력을 1개로 만드는 방식이 필요합니다. Tile Coding에서도 상태와 행동을 함께 입력으로 넣을 수 있습니다.

---

### Episodic Sarsa with Function Approximation

테이블 Sarsa와의 차이는 두 가지뿐입니다.

| 항목 | 테이블 Sarsa | 함수 근사 Sarsa |
| :--- | :--- | :--- |
| 행동 가치 | $Q(s, a)$ 직접 저장 | $\hat{q}(s, a, \mathbf{w})$ |
| 업데이트 | $Q(S, A) \leftarrow Q(S, A) + \alpha \delta$ | $\mathbf{w} \leftarrow \mathbf{w} + \alpha \delta \nabla \hat{q}(S, A, \mathbf{w})$ |

TD 오차 $\delta = R + \gamma \hat{q}(S', A', \mathbf{w}) - \hat{q}(S, A, \mathbf{w})$ 는 동일합니다.

### Episodic Sarsa in Mountain Car

---

## 한 줄 요약

Mountain Car 문제에 Tile Coding + Episodic Sarsa를 적용하여, **낙관적 초기화(optimistic initialization)**가 탐험을 유도하고 학습 곡선에서 스텝 크기 $\alpha$의 역할을 확인합니다.

---

## 핵심 개념 정리

### Mountain Car 환경

- **상태**: (위치, 속도) — 2차원 연속값
- **행동**: 앞으로 가속 / 뒤로 가속 / 코스트(관성)
- **보상**: 매 타임스텝마다 $-1$ (에피소드를 빠르게 끝낼수록 유리)
- **목표**: 오른쪽 산 꼭대기 도달
- **핵심 난이도**: 차의 엔진이 약해 직접 올라갈 수 없음. 반드시 왼쪽 경사면을 타고 올라가 운동량을 얻은 뒤 오른쪽으로 탈출해야 합니다.

---

### 특징 설계

- **Tile Coding**: 위치·속도 2차원 입력에 8×8 격자, 8개 Tiling
- **스텝 크기 스케일링**: 활성 특징 수 = 항상 8 (Tiling 수) → $\alpha$를 8로 나눔

$$\alpha_{\text{effective}} = \frac{\alpha}{\|\mathbf{x}\|_1} = \frac{\alpha}{8}$$

- **행동 처리**: Feature Stacking (3개 행동)

---

### 낙관적 초기화 (Optimistic Initialization)

가중치를 모두 **0으로 초기화**했는데 이것이 사실 낙관적(optimistic)입니다.

- 보상은 매 스텝 $-1$이므로 모든 정책의 참 가치는 **음수**입니다.
- 초기 추정값 = 0 > 참 가치 → 낙관적 초기화!
- 에이전트는 "이 상태가 좋을 것"이라 기대하고 방문하지만, 실제로는 $-1$ 보상을 받습니다. 이 실망이 탐험을 유도합니다.
- 추가 랜덤 탐험($\epsilon$-greedy) 없이 greedy 행동만으로도 충분한 탐험이 이루어집니다.

---

### 학습 곡선 분석

| $\alpha$ (8로 나누기 전) | 학습 속도 | 최종 성능 |
| :--- | :--- | :--- |
| 0.1 | 느림 | 보통 |
| 0.5 | 빠름 | 더 좋음 |

500 에피소드 후 모든 $\alpha$에서 수렴. 더 큰 $\alpha$가 초기 학습에서 유리합니다.

> 수렴된 가치 함수에서 흥미로운 패턴: 출발 위치(상태 500 근처)에서 약 120 스텝 필요. 목표 근처이지만 속도가 낮은 상태는 예상보다 더 많은 스텝이 필요합니다 (다시 후진해 운동량을 얻어야 하므로).

## 이전 내용과의 연결 / 다음으로 이어지는 흐름

Sarsa를 실제 문제에 적용했습니다. 다음 영상에서는 Sarsa를 **Expected Sarsa와 Q-learning**으로 확장합니다.

---

### Expected Sarsa with Function Approximation

---

## 한 줄 요약

Sarsa의 다음 행동 가치 샘플을 **목표 정책의 기댓값**으로 대체하면 Expected Sarsa, **최댓값**으로 대체하면 Q-learning이 됩니다. 함수 근사 설정에서도 변경점은 타깃 계산 방식뿐입니다.

---

## 핵심 개념 정리

### Sarsa → Expected Sarsa → Q-learning

| 알고리즘 | TD 타깃 |
| :--- | :--- |
| Sarsa | $R + \gamma \hat{q}(S', A', \mathbf{w})$ |
| Expected Sarsa | $R + \gamma \sum_a \pi(a \mid S') \hat{q}(S', a, \mathbf{w})$ |
| Q-learning | $R + \gamma \max_a \hat{q}(S', a, \mathbf{w})$ |

Q-learning은 목표 정책이 greedy일 때의 Expected Sarsa 특수 사례입니다. Greedy 정책에 대한 기댓값 = 최댓값이기 때문입니다.

함수 근사 업데이트 규칙은 타깃만 다르고 나머지 구조는 동일합니다:

$$\mathbf{w} \leftarrow \mathbf{w} + \alpha \left[ \text{target} - \hat{q}(S, A, \mathbf{w}) \right] \nabla \hat{q}(S, A, \mathbf{w})$$

## 이전 내용과의 연결 / 다음으로 이어지는 흐름

함수 근사 설정의 주요 제어 알고리즘(Sarsa / Expected Sarsa / Q-learning)을 완성했습니다. 다음 영상에서는 함수 근사 환경에서의 **탐험**이 테이블 방식과 어떻게 다른지를 다룹니다.

### Exploration under Function Approximation

---

## 한 줄 요약

함수 근사에서 낙관적 초기화는 일반화 효과 때문에 테이블 방식처럼 체계적인 탐험을 보장하지 못하는 경우가 많습니다. **$\epsilon$-greedy**가 현실적으로 가장 무난한 탐험 전략입니다.

---

## 핵심 개념 정리

### 테이블 방식에서의 낙관적 초기화

각 상태의 가치를 독립적으로 저장하므로, 한 상태를 방문해 업데이트해도 다른 상태의 초기 낙관값이 그대로 유지됩니다. → 아직 방문하지 않은 상태는 여전히 매력적 → **체계적 탐험** 자연스럽게 발생.

---

### 함수 근사에서의 문제

**문제 1: 초기화 어려움**

- 이진 특징: 최대 가능 리턴으로 가중치 초기화 → 낙관적 가치 보장 가능
- 신경망 (tanh 활성화): 가중치가 양수여도 출력이 음수일 수 있음 → 초기화만으로 낙관값 보장 불가

**문제 2: 일반화에 의한 낙관값 훼손**

일반화로 인해 방문하지 않은 상태의 가치도 이미 업데이트될 수 있습니다.

극단 예시: 특징이 하나이고 항상 1인 경우 → 한 상태 업데이트 = 모든 상태 업데이트. 어떤 상태를 방문하기 전에 이미 낙관값이 사라집니다.

체계적 탐험을 위해서는 **업데이트가 국소적(localized)**이어야 합니다.
- Tile Coding: 국소적 업데이트 가능 → 낙관적 초기화 효과 있음
- 신경망: 일반화가 강할 경우 낙관값이 빠르게 사라짐

---

### $\epsilon$-greedy: 범용 탐험 전략

- 함수 근사 방식에 관계없이 적용 가능
- 초기화 방식과 무관
- 단점: 비방향적(undirected) 탐험 → 현재 정책 근방에서 랜덤 탐험만 함. 낙관적 초기화처럼 체계적이지 않음.

> 함수 근사 환경에서의 효과적인 탐험은 아직 열린 연구 문제입니다. 이 수업에서는 $\epsilon$-greedy를 계속 사용합니다.

---

# Part 3: Average Reward

---

### Average Reward: A New Way of Formulating Control Problems

---

## 한 줄 요약

**연속 과제(continuing task)**에서 할인율 $\gamma$는 문제 구조에 따라 적절한 값이 달라지는 한계가 있습니다. **평균 보상(Average Reward)**은 할인 없이 장기 보상률을 직접 최적화하는 새로운 목적 함수입니다.

---

## 핵심 개념 정리

### 할인 방식의 문제: Nearsighted MDP 예시

두 링이 교차하는 구조(각 링 5개 상태). 상태 $S$에서 왼쪽/오른쪽 링 중 하나를 선택합니다.

- 왼쪽 링: $S$ 직후에 $+1$ 보상
- 오른쪽 링: $S$ 직전에 $+2$ 보상

직관적으로는 오른쪽이 더 좋지만, 할인 방식에서는 $\gamma$ 값에 따라 결론이 달라집니다.

| $\gamma$ | $V_L(S)$ | $V_R(S)$ | 선호 정책 |
| :--- | :--- | :--- | :--- |
| 0.5 | ≈ 1.0 | ≈ 0.1 | **왼쪽** |
| 0.9 | ≈ 2.4 | ≈ 3.2 | **오른쪽** |

오른쪽을 선호하려면 $\gamma \geq 0.841$ 이어야 합니다. 링이 100개 상태로 구성되면 $\gamma > 0.99$ 가 필요합니다.

> $\gamma \to 1$은 무한 리턴, $\gamma$가 크면 분산도 커져 학습이 어려워집니다. 해결책이 필요합니다.

---

### 평균 보상 (Average Reward)

$$\bar{r}(\pi) = \lim_{H \to \infty} \frac{1}{H} \sum_{t=1}^H \mathbb{E}[R_t \mid \pi]$$

더 일반적으로, 상태 방문 분포 $\mu$를 이용:

$$\bar{r}(\pi) = \sum_s \mu(s) \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \cdot r$$

- 에이전트의 **보상 획득 속도(rate of reward)**를 직접 최대화
- 근거리 보상과 원거리 보상을 동등하게 취급
- $\gamma$ 선택 불필요

Nearsighted MDP 예시:
- 왼쪽 정책: 5개 상태 균일 방문, $+1$이 한 번 → $\bar{r}_L = 1/5 = 0.2$
- 오른쪽 정책: 5개 상태 균일 방문, $+2$가 한 번 → $\bar{r}_R = 2/5 = 0.4$

→ 오른쪽이 명확히 우월. $\gamma$를 조정할 필요 없음.

---

### 미분 리턴 (Differential Return)

평균 보상 설정에서의 리턴은 **각 보상에서 평균 보상을 뺀 합**입니다.

$$G_t = \sum_{k=0}^{\infty} \left( R_{t+k+1} - \bar{r}(\pi) \right)$$

이 합이 수렴하려면 뺄 상수가 정확히 $\bar{r}(\pi)$여야 합니다. 다른 값을 빼면 $\pm\infty$로 발산합니다.

**직관**: 미분 리턴 = "이 상태·행동에서 시작했을 때, 평균 대비 얼마나 더 (또는 덜) 보상을 받는가?"

---

### Nearsighted MDP에서의 미분 리턴 계산

$\pi_L$을 따를 때 ($\bar{r} = 0.2$):

| $S$에서 선택 | 미분 리턴 |
| :--- | :--- |
| 왼쪽 행동 | $+0.4$ |
| 오른쪽 행동 (한 번 후 $\pi_L$) | $+1.4$ |

→ 오른쪽 행동이 더 높은 미분 리턴 → 정책 개선 시 오른쪽으로 전환.

$\pi_R$을 따를 때 ($\bar{r} = 0.4$):

| $S$에서 선택 | 미분 리턴 |
| :--- | :--- |
| 오른쪽 행동 | $-0.8$ |
| 왼쪽 행동 (한 번 후 $\pi_R$) | $-1.8$ |

→ 오른쪽이 더 높음 → 오른쪽 유지 확인.

> 중요: 미분 리턴은 **같은 정책 내에서 행동 간 비교**에만 사용해야 합니다. 정책 간 비교는 $\bar{r}(\pi)$를 사용합니다.

---

### 미분 가치 함수와 미분 Sarsa

미분 가치 함수: $v_\pi(s) = \mathbb{E}\left[ G_t \mid S_t = s, \pi \right]$

벨만 방정식 (할인 없음, 평균 보상 차감):

$$v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[ r - \bar{r}(\pi) + v_\pi(s') \right]$$

**Differential Sarsa** 업데이트:

$$\delta = R - \bar{R} + \hat{q}(S', A', \mathbf{w}) - \hat{q}(S, A, \mathbf{w})$$
$$\mathbf{w} \leftarrow \mathbf{w} + \alpha \delta \nabla \hat{q}(S, A, \mathbf{w})$$
$$\bar{R} \leftarrow \bar{R} + \beta \delta \quad \text{(평균 보상 추정 업데이트)}$$

기존 Sarsa와의 차이: $\gamma$가 없고, 보상에서 $\bar{R}$을 빼며, 평균 보상 추정치를 따로 관리합니다.

---

## 비교 / 정리 표

| 항목 | 할인(Discounted) 방식 | 평균 보상(Average Reward) 방식 |
| :--- | :--- | :--- |
| 목적 함수 | $\mathbb{E}\left[\sum \gamma^t R_t\right]$ | $\bar{r}(\pi) = $ 단위 시간당 보상률 |
| $\gamma$ | 문제마다 튜닝 필요 | 불필요 |
| 리턴 정의 | 할인 합 | 미분 리턴 ($R_t - \bar{r}$의 합) |
| 수렴 문제 | $\gamma \to 1$ 시 분산 폭발 | 없음 |
| 적합한 과제 | 에피소드/연속 모두 | **연속 과제** |

## 한 줄 요약

표준 RL은 보상 함수가 주어진다고 가정하지만, **보상 함수 자체를 설계·학습하는 문제**를 다룹니다. 에이전트 설계자의 목적을 외재적 보상(extrinsic reward)으로, 에이전트가 실제로 최적화하는 것을 내재적 보상(intrinsic reward)으로 분리하는 틀을 제안합니다.

---

## 핵심 개념 정리

### 선호-파라미터 혼동 (Preferences-Parameters Confound)

표준 RL의 단일 보상 함수는 두 가지 역할을 동시에 수행합니다.

| 역할 | 의미 |
| :--- | :--- |
| **선호(Preferences)** | 에이전트 설계자가 어떤 행동을 원하는지 표현 |
| **파라미터(Parameters)** | 에이전트의 목표·행동을 결정하는 RL 알고리즘의 파라미터 |

Singh의 주장: 이 두 역할은 구분되어야 하며, **두 개의 보상 함수**로 분리할 수 있습니다.

- $R_0$ (외재적 보상): 설계자의 진짜 목적 — 변경 불가
- $R_i$ (내재적 보상): 에이전트가 실제로 최적화하는 함수 — 설계하거나 학습 가능

---

### 최적 보상 문제 (Optimal Reward Problem)

**"$R_i$를 어떻게 설정해야 에이전트가 $R_i$를 최적화하는 과정에서 $R_0$도 최대화하는가?"**

메타 최적화 구조:
```
외부 루프: R_i를 최적화 (R_0 기준으로)
  └─ 내부 루프: R_i가 주어졌을 때 에이전트가 행동 최적화
```

---

### 해결 방법 1: PGRD (Policy Gradient for Reward Design)

핵심 통찰: 내재적 보상을 정책의 파라미터로 볼 수 있습니다. 정책 그래디언트가 정책 파라미터를 최적화하듯, **외재적 보상에 대한 그래디언트로 내재적 보상 파라미터를 업데이트**합니다.

Atari 25개 게임에서 UCT 계획 알고리즘과 결합: 대부분 게임에서 성능 향상.

---

### 해결 방법 2: Meta-Gradient Approach

학습 알고리즘(Actor-Critic)을 통해 그래디언트를 역전파해 내재적 보상을 업데이트합니다.

1. Actor-Critic이 내재적 보상으로 정책 파라미터 업데이트
2. Meta-gradient가 정책 파라미터 변화에 대한 그래디언트로 내재적 보상 파라미터 업데이트

Atari 여러 게임에서 외재적 보상만 사용할 때보다 **상당한 성능 향상** (내재적 보상만 학습).

---

### 내재적 보상의 활용 가능성

- **제한된 에이전트 극복**: 에이전트가 계산적으로 제한되어 있을 때, 잘 설계된 내재적 보상으로 더 나은 행동 유도
- **가치 정렬(Value Alignment)**: 사용자와 에이전트 설계자 간 목표 일치
- **평생 학습(Lifelong Learning)**: 지속적으로 변하는 환경에서의 적응
