# Module 5 — Planning, Learning & Acting

---

### What is a Model? 

---

## 한 줄 요약

모델은 환경 동역학에 대한 지식을 저장하며, **시뮬레이션된 경험으로 계획(planning)을 가능하게** 합니다. 모델의 종류는 Sample Model과 Distribution Model로 나뉘며, 각각 다른 트레이드오프를 가집니다.

---

## 핵심 개념 정리

### 왜 모델이 필요한가

지금까지 배운 방법들의 위치를 정리하면:

```
TD / MC          → 실제 경험에서만 학습, 모델 불필요
Dynamic Programming → 완전한 환경 모델로 계획, 경험 불필요
Dyna (이번 모듈)  → 둘을 결합: 실제 경험 + 모델 기반 시뮬레이션
```

**모델**: 상태 s에서 행동 a를 취했을 때 다음 상태 s'와 보상 r을 생성하는 것입니다. 실제로 행동하지 않고도 결과를 미리 볼 수 있게 해줍니다.

**Planning**: 모델을 사용해 시뮬레이션된 경험을 생성하고, 그 경험으로 가치 함수를 업데이트해 정책을 개선하는 과정입니다.

> 시뮬레이션 경험을 추가하면 에이전트가 실제 환경과 상호작용하는 횟수를 줄이면서도 같은 수준의 정책에 도달할 수 있습니다. 이것이 **sample efficiency** 향상의 핵심입니다.

---

### Sample Model vs Distribution Model

| 항목 | Sample Model | Distribution Model |
| :--- | :--- | :--- |
| 출력 | 확률에 따라 샘플링된 단일 결과 | 모든 가능한 결과의 확률 분포 |
| 메모리 | 적음 (규칙만 저장) | 많음 (모든 결과 열거) |
| 기댓값 계산 | 근사 (많은 샘플 평균) | 정확 (확률 가중 합산) |
| 리스크 정량화 | 불가 | 가능 |
| 계산 비용 | 낮음 | 높음 |

**동전 5개 예시:**
- Sample Model: 0 또는 1을 독립적으로 5번 뽑음 → 규칙 하나로 끝
- Distribution Model: $2^5 = 32$가지 결과 전체에 확률 부여 필요

**주사위 12개 예시:**
- Sample Model: 1~6 사이 숫자를 12번 뽑음 → 간단
- Distribution Model: $6^{12} = 약 20억$가지 결과 전체를 기술해야 함

---

### 어떤 모델을 써야 하는가

**Sample Model이 유리한 경우**: 메모리가 제한적이거나, 정확한 확률보다 샘플 자체가 필요한 경우. RL에서 시뮬레이션 경험을 생성할 때 대부분 해당됩니다.

**Distribution Model이 유리한 경우**: 정확한 기댓값이 필요하거나, 리스크를 정량화해야 하는 경우. 예를 들어 의사가 약을 처방할 때 부작용의 정확한 발생 확률을 알아야 하는 상황입니다.

Distribution Model은 Sample Model로도 사용할 수 있습니다(확률에 따라 샘플링하면 됨). 반대는 불가능합니다.

### Random Tabular Q-planning

---

## 한 줄 요약

Q-learning의 업데이트 구조를 **실제 경험 대신 모델에서 생성한 시뮬레이션 경험**에 적용하면, 환경과 상호작용하지 않고도 정책을 개선할 수 있습니다.

---

## 핵심 개념 정리

### Q-learning vs Q-planning

구조는 동일하고 경험의 출처만 다릅니다.

| 항목 | Q-learning | Q-planning |
| :--- | :--- | :--- |
| 경험 출처 | 실제 환경 | 모델 (시뮬레이션) |
| 업데이트 수식 | Q-learning update | 동일 |
| 환경 상호작용 필요 | ✅ | ❌ |

### Random-Sample One-Step Tabular Q-planning 알고리즘

```
1. 모든 (s, a) 중 하나를 무작위 선택
2. 샘플 모델에 (s, a)를 입력 → (s', r) 생성
3. Q-learning 업데이트 수행
   Q(s,a) ← Q(s,a) + α[r + γ max_a' Q(s',a') - Q(s,a)]
4. 업데이트된 Q로 greedy 정책 개선
5. 반복
```

핵심은 **실제로 그 행동을 취하지 않아도** 된다는 점입니다. 모델이 결과를 대신 생성해줍니다.

---

### Planning Update를 언제 실행하는가

실제 환경에서 행동을 취하는 시점과 학습 업데이트 실행 속도 사이에는 간격이 있습니다. 이 유휴 시간(waiting time)을 Planning Update로 채울 수 있습니다.

> 절벽 근처에 서 있는 로봇 예시가 인상적이었습니다. 모델은 절벽에서 떨어지는 결과를 알고 있지만, 가치 함수에 아직 반영이 안 된 상태입니다. 실제로 떨어지지 않고도 시뮬레이션 경험을 반복해 가치 함수를 업데이트하면, 로봇은 절벽을 피하는 정책을 학습할 수 있습니다. 경험 없이 상상만으로 위험을 배우는 것입니다.

Planning은 실제 상호작용 루프와 병렬로 실행될 수 있습니다. 환경과 상호작용하는 횟수(sample efficiency)를 줄이면서도 동일한 정책 품질에 도달하는 것이 목표입니다.

### Dyna as a Formalism for Planning

#### (The Dyna Architecture / The Dyna Algorithm / Dyna & Q-learning in a Simple Maze)

---

## 한 줄 요약

Dyna는 실제 환경 경험(direct RL)과 모델 기반 시뮬레이션(planning)을 하나의 루프로 통합한 아키텍처로, **같은 환경 상호작용으로 훨씬 빠르게 학습**합니다.

---

## 핵심 개념 정리

### Dyna 아키텍처의 구성 요소

```
환경 → 실제 경험
         ├─ Direct RL Update  (Q-learning 업데이트)
         └─ Model Learning    (경험으로 모델 갱신)
              └─ Search Control → 모델에서 (s,a) 샘플링
                   └─ Planning Update  (시뮬레이션 경험으로 Q-learning 업데이트)
```

두 가지 경험 출처가 **동일한 가치 함수**를 공유하며 업데이트합니다.

| 구성 요소 | 역할 |
| :--- | :--- |
| Direct RL | 실제 전이로 Q 업데이트 |
| Model Learning | 실제 전이를 모델에 저장 |
| Search Control | 계획할 (s,a) 선택 |
| Planning Update | 시뮬레이션 전이로 Q 업데이트 |

---

### Tabular Dyna-Q 알고리즘

Dyna-Q는 **결정론적 전이**를 가정합니다. 한 번 경험한 (s,a) → (s',r)은 항상 동일하게 재현됩니다.

```
매 스텝:
1. ε-greedy로 행동 선택
2. 환경에서 (s, a, r, s') 관측
3. Q-learning 업데이트 (Direct RL)
4. 모델에 (s,a) → (s',r) 저장 (Model Learning)
5. n번 반복 (Planning):
   a. 방문한 적 있는 (s,a) 무작위 선택 (Search Control)
   b. 모델에서 (s',r) 조회
   c. Q-learning 업데이트
```

Q-learning = Dyna-Q에서 5번 단계(planning)를 제거한 특수 케이스입니다.

---

### 미로 실험: Planning 횟수에 따른 성능 비교

- 환경: 소형 미로, 목표 도달 시 +1, 나머지 0, $\gamma = 0.95$
- $\alpha = 0.1$, $\epsilon = 0.1$, 50 에피소드 × 30회 평균

| 에이전트 | Planning 횟수/스텝 | 특성 |
| :--- | :--- | :--- |
| Q-learning | 0 | 느리게 수렴, 약 14스텝에서 정체 |
| Dyna-Q (n=5) | 5 | Q-learning과 동일 성능, 훨씬 빠르게 도달 |
| Dyna-Q (n=50) | 50 | **3 에피소드 만에** 좋은 정책 발견 |

> 2 에피소드 후 Q-learning은 수백 스텝이 필요한 정책을 갖고 있지만, Dyna-Q(n=50)는 이미 효율적인 경로를 알고 있습니다. 환경과의 상호작용 횟수는 동일한데도 학습량이 극적으로 다릅니다.

---

### Search Control의 한계 — 무작위 샘플링의 비효율

Dyna-Q는 search control에서 이미 방문한 (s,a)를 **무작위로** 선택합니다. 이 방식의 문제는 보상이 희소한 환경에서 TD 오차가 0인 전이를 반복 샘플링하는 경우가 많다는 것입니다. 업데이트가 가치 함수를 전혀 바꾸지 못합니다.

100번의 planning 스텝 중 실제로 가치 함수를 변경한 것이 단 2개뿐인 경우도 발생했습니다.

방문 순서를 효율적으로 정렬하면 동일한 성능을 **1/6의 planning 스텝**으로 달성할 수 있습니다. 이 주제는 교재 8.4절(Prioritized Sweeping)로 이어집니다.

### Dealing with Inaccurate Models

#### (What if the model is inaccurate? / In-depth with changing environments)

---

## 한 줄 요약

모델이 부정확하면 planning이 오히려 정책을 망칩니다. 부정확성의 원인은 **불완전한 모델(미방문 전이)**과 **환경 변화** 두 가지이며, Dyna-Q+는 탐험 보너스로 후자를 해결합니다.

---

## 핵심 개념 정리

### 모델이 부정확해지는 두 가지 원인

| 원인 | 설명 | 영향 |
| :--- | :--- | :--- |
| 불완전한 모델 (Incomplete) | 아직 방문하지 않은 (s,a)의 전이가 없음 | 해당 (s,a)로 planning 불가 |
| 환경 변화 (Inaccurate) | 환경이 바뀌어 저장된 전이와 실제가 달라짐 | planning이 잘못된 방향으로 Q 업데이트 |

Planning은 "모델이 맞다"는 가정 하에 작동합니다. 모델이 틀리면 policy는 환경이 아닌 잘못된 모델에 최적화됩니다.

---

### 불완전한 모델에서 Dyna-Q가 작동하는 방법

Dyna-Q의 search control은 **이미 방문한 (s,a)만 샘플링**합니다. 모델이 모르는 전이는 planning에 사용되지 않습니다.

초반에는 방문한 (s,a)가 적어 같은 전이를 반복 planning하지만, 에이전트가 더 많은 상태를 방문할수록 planning 업데이트가 상태 공간 전체에 고르게 분산됩니다.

---

### 환경 변화 → 새로운 탐험-활용 트레이드오프

환경이 변하면 모델의 일부 전이가 틀려집니다. 에이전트는 선택해야 합니다.

- **탐험**: 오래 방문하지 않은 상태를 재방문해 모델을 최신화
- **활용**: 현재 모델이 맞다고 가정하고 최적 정책 실행

오랫동안 방문하지 않은 상태일수록 모델이 틀렸을 가능성이 높습니다.

---

### Dyna-Q+ — 탐험 보너스로 해결

Planning 업데이트 시 reward에 보너스를 추가합니다.

$$r' = r + \kappa \sqrt{\tau}$$

- $\tau$: 해당 (s,a)를 마지막으로 **실제 환경에서** 방문한 이후 경과 시간
- $\kappa$: 보너스 강도를 조절하는 작은 상수

> $\tau$는 planning 루프에서 업데이트되지 않습니다. 실제 방문이 아니기 때문입니다. 오직 실제 환경 상호작용에서만 갱신됩니다.

오래 방문하지 않은 (s,a)일수록 $\tau$가 커지고 보너스가 커집니다. 결국 planning이 그 (s,a)를 향한 정책을 만들어내고, 에이전트가 실제로 방문해 모델을 업데이트하게 됩니다.

---

### Shortcut Maze 실험: Dyna-Q vs Dyna-Q+

환경 설정: 초반에는 벽으로 막힌 미로, 실험 중반에 오른쪽 벽에 지름길이 생깁니다.

**지름길 생성 전**: 두 알고리즘 성능 유사. Dyna-Q+의 추가 탐험이 약간 더 빠른 초기 학습에 기여.

**지름길 생성 후**:

| 알고리즘 | 지름길 발견 | 이유 |
| :--- | :--- | :--- |
| Dyna-Q+ | 변화 직후 빠르게 발견 | 오래된 상태 탐험 보너스로 자동 재방문 |
| Dyna-Q | 실험 내 발견 못함 | $\epsilon$-greedy만으로는 7번 연속 탐험 행동 필요 |

> Dyna-Q도 결국 지름길을 찾을 수 있지만, $\epsilon$-greedy로 정확한 경로를 우연히 탐험하려면 매우 긴 시간이 필요합니다. Dyna-Q+는 체계적으로 오래된 상태를 재방문하기 때문에 환경 변화에 훨씬 빠르게 적응합니다.
